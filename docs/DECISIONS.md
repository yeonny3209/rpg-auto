# 결정 기록

형식: `날짜 — 결정 — 이유`

## 2026-11-27 (첫 실행)
- **기술 스택: TypeScript + Three.js + Vite** — 웹 브라우저 3D 표준에 가깝고, 무료이며, 이 클라우드 환경에서 Node로 빌드하고 Playwright(헤드리스 Chromium)로 실행·스크린샷 검증까지 가능하다. Unity/Godot은 이 환경에서 실행 검증이 어렵다.
- **테스트: Vitest** — Vite와 설정을 공유하고 빠르다. 게임 로직(`src/logic/`)만 테스트 대상으로 한다.
- **로직/렌더링 분리** — `src/logic/`은 Three.js를 import하지 않는다. 밸런스 수치는 `data/*.json`.
- **물리 엔진 없음(초기)** — 평지 + 간단한 원형 충돌로 시작. 지형·복잡한 충돌이 필요해지면 그때 검토(Rapier 등 무료 WASM).
- **게임 이름 "잔불의 대지"** — 빛/어둠 대비를 시각·시스템(봉화, 잔불) 양쪽에 쓰기 위해.
- **최대 레벨 40, 시작 클래스 3종 + 15레벨 전문화** — 1인 개발·자동 개발 범위에서 끝까지 만들 수 있는 크기로 제한.
- **죽음 페널티는 미각인 잔불 50%만** — 긴장감은 주되 장비·경험치 손실로 좌절시키지 않기 위해.
- **에셋은 코드 생성 도형만** — 저작권 문제 원천 차단. 추후에도 CC0 등 출처 명확한 것만.
- **멀티플레이는 후반** — 1인용 수직 슬라이스가 재미있어진 뒤 WebRTC 협동을 검토.
- **상호작용 키 F (GDD의 E에서 변경)** — E는 카메라 회전(Q/E)에 쓰기로 해서 충돌을 피함. GDD 조작 표도 수정.
- **우클릭 = 강공격 차지, 휠클릭 드래그 = 카메라 회전** — 마우스 두 버튼을 모두 공격에 써서 손이 키보드 홈 위치를 떠나지 않게.
- **잔불 각인 비용은 레벨마다 20씩 증가(20, 40, 60…), 레벨당 공격력 +1%·최대 HP +3** — 초반엔 빨리 체감, 후반엔 완만하게.
- **사망 시 기존 흔적은 사라지고 새 흔적만 남음** — 소울류 규칙. 긴장감 유지.
- **저장은 localStorage + 버전 필드 + 단계별 마이그레이션(v1→v2→v3)** — 서버 없이 무료, 구조가 바뀌어도 기존 저장을 살림.
- **아이템 등급 가중치 60/28/9/2.6/0.4** — 전설은 약 250개 중 1개. 보스·엔드 콘텐츠에서 luck 보정으로 올릴 예정.
- **`window.__game` 디버그 핸들 유지** — 헤드리스 검증 스크립트가 게임 상태를 직접 확인하기 위해. 플레이에는 영향 없음.

## 2026-11-28 (2번째 실행)
- **`main.ts`를 모듈로 분리, 공유 상태는 `core.ts`에 둔다** — 모든 모듈이 `core`에서 가져가고 `core`는 다른 모듈을 import하지 않는다(타입만 예외). 모듈끼리 서로 호출하는 순환은 함수 호출 시점에만 일어나서 안전하다.
- **클래스는 "보너스 합산 + 공격 배율" 방식** — 장비 보너스와 같은 모양(`GearBonus`)으로 더하고, 공격 범위·각도·속도·스태미나는 배율로 바꾼다. 클래스별 시작 속성 포인트 합은 같게 해서 공정하게 시작.
- **기존(v3) 저장은 선봉으로 이어가고, 클래스 없는 저장은 선택 화면을 다시 띄운다** — 저장 호환을 지키면서 새 시스템 도입.
- **스킬은 4종 효과 타입(arc/ring/dash/buff)을 데이터로 조합** — 새 스킬을 코드 없이 JSON으로 추가할 수 있게. 스킬 적중은 잔불 게이지를 채우지 않는다(무한 연쇄 방지).
- **퀘스트 목표는 처치/봉화 점화 두 종류로 시작** — 이벤트 보고 한 줄(`reportQuest`)로 연결. 아이템 수집·대화 목표는 필요해질 때 추가.
- **저장 데이터는 읽을 때 `sanitize`로 정리** — 알 수 없는 퀘스트·초과 진행도는 버려서 데이터가 바뀌어도 저장이 깨지지 않게.
- **지형은 값 노이즈 3옥타브 × 평탄화 마스크, 높이 y는 매 프레임 `heightAt`으로 갱신** — 물리 엔진 없이 시각적 굴곡만. 마을·봉화 주변은 완전 평지라 기존 배치와 충돌 없음.
- **시작 지점 적 배치는 `?demo`에서만** — 일반 플레이 첫 화면을 조용하게, 테스트는 결정적으로.
- **튜토리얼 진행도는 별도 localStorage 키** — 게임 저장 형식을 또 올리지 않기 위해.

## 2026-11-28 (3번째 실행)
- **보스는 상태 기계 + 데이터 패턴(`data/bosses.json`)** — 패턴 선택은 순수 함수(`nextPattern`)로 분리해 테스트. 같은 패턴 연속 금지, 근거리는 내려찍기·원거리는 돌진/가시 선호. 위험 공격은 반드시 예고(붉은 원, 방향 고정 시점)로 "피할 수 있는 난이도"를 지킴.
- **보스는 일반 적 시스템에 `ai: "boss"`로 얹음** — 별도 엔티티를 만들지 않고 `Enemy.boss` 런타임 필드만 추가. 스폰 가중치 0으로 일반 스폰에서 제외.
- **상점 재고는 레벨별 시드 고정, 판매가 = 매입가 × 0.4** — 새로고침으로 좋은 물건을 뽑는 행동을 막고 되팔기 차익을 없앰. 무한 재고는 일단 단순함 우선.
- **어둠은 "가장 가까운 밝은 봉화 거리"의 선형 함수** — 봉화 점화에 즉각적 가치를 주고(피해 감소·시야 확보), 별도 상태를 저장하지 않아 저장 호환에 영향 없음. 변화는 부드럽게(보간).
- **강화 실패는 골드만 소모, 단계 하락·파괴 없음** — 사냥 보람을 해치는 손실을 피함. 재미는 성공률 곡선과 비용으로. 스탯은 `base × (1 + 0.08 × plus)`로 매번 재계산해 반올림 누적 오차 없음(`base` 필드 저장).
- **밸런스 테스트는 "방향 점검" 용도** — 이동·회피를 15초/킬 가정으로 두고 범위 단언. 임계값이 실제 재미를 보장하지 않으며, 사람이 플레이해 조정할 때 같이 고친다.

## 2026-11-28 (4번째 실행)
- **겹쳐 쌓는 가방(`bag`)은 장비 인벤토리와 분리** — 소모품·재료는 id→수량 맵, 종류별 최대 수량(`data/materials.json`). 한 칸씩 차지하지 않아 장비 가방이 안 막히고, 저장 정리(`sanitizeBag`)가 단순하다.
- **제작은 "재료+골드 → 즉시 결과", 결과 장비는 현재 레벨 기준** — 가방이 가득하면 재료를 쓰지 않고 거부(손해 방지). 레시피는 데이터(`recipes.json`).
- **보스 시스템은 보스 id로 일반화** — 새 보스 = `enemies.json` + `bosses.json` 항목만 추가(패턴 부분집합 가능). 코드의 `"boarKing"` 하드코딩 제거.
- **스킬 수련은 원본 데이터를 건드리지 않는 "스케일 사본"** — `scaledSkill`이 효과·쿨타임만 바꿔 돌려주고, 저장은 2레벨 이상만 기록. 클래스를 바꿔도 단계가 보존된다.
- **클래스 변경은 비용(레벨×100)+2단계 확인** — 실수 방지. 능력치는 시작 능력치만 교체하고 투자분은 유지.
- **소품 배치는 순수 함수 + 비움 구역** — 봉화·보스 자리·마을 위에 바위·나무가 놓이지 않도록 테스트로 보장.
- **UI 레이아웃이 호버로 흔들리면 안 된다** — 툴팁 영역은 최소 높이 고정(헤드리스 호버 테스트가 발견).

## 2026-11-28 (5번째 실행)
- **전문화는 "스킬 교체(id 기준) + 보너스 스탯"** — 슬롯 순서를 유지한 채 `replaces` 스킬만 바꿔서 스킬바·단축키가 안 흔들림. 재선택은 비용을 받고, 클래스를 바꾸면 전문화는 자동 해제(검증 함수 `validSpec`).
- **의뢰는 시드 기반 목록 + 완료/포기 시 시드 증가** — 새로고침으로 목록을 뽑는 행동 방지, 저장은 시드·진행 중 의뢰·완료 수만.
- **아이콘은 외부 에셋 없이 인라인 SVG** — 종류별 경로 + currentColor로 희귀도 색을 받음.
- **상점 품절은 세션 한정** — 재고가 레벨 시드 고정이라 저장 없이 단순하게 처리. 저장이 필요하면 이후 저장 버전 상향.

## 2026-11-28 (6번째 실행)
- **지역은 원형 영역 + 통로 선분(`regions.json`)** — 하나의 큰 바닥 판 위에 지역별 팔레트·안개·적 풀을 얹는다. 이동 제한은 `clampWalkable` 한 함수. 새 지역 = 데이터 항목 추가 + 봉화/적/보스 데이터.
- **적의 지역 소속은 `regions.json`의 `enemies` 목록** — `enemies.json`에 region 필드를 넣지 않아 JSON 타입이 깨지지 않고, 지역별 스폰 가중치는 기존 `spawnWeight`를 재사용.
- **숲 보스는 기존 보스 시스템 재사용(`mireMother`)** — 패턴은 멧돼지왕과 같은 부분집합, 수치만 상향. 새 패턴은 이후.
- **빠른이동은 "밝힌 봉화 곁에서만, 밝힌 봉화로, 거리 비례 골드(최소 10)"** — 마을 귀환이 공짜가 되면 어둠·거리 부담이 사라져서 비용을 둠. 도착 시 부활 봉화로 지정.
- **숲 경험치는 레벨당 약 23마리로 맞춤** — 처음 값(14마리)은 너무 빨라서 하향. 테스트가 범위(20~120)를 지킨다.

## 2026-11-28 (사용자 결정: 멀티플레이)
- **협동 방식**: 같은 서버 월드에서 함께 사냥(1) + 파티 보스전(2). 인원 5~10명.
- **서버**: 무료/저가 클라우드(Fly.io·Render 등). 24시간 접속 가능, 소규모는 거의 무료~월 몇 달러.
- **저장**: 서버에 계정별 저장(닉네임+비밀번호). 현재 localStorage 세이브(v8)를 서버로 옮긴다.
- 원칙: 솔로 플레이가 깨지면 안 된다. 로직(src/logic)은 서버·클라가 공유하므로 렌더링 무관 규칙을 유지한다.

## 2026-11-28 (15시 실행, 멀티플레이)
- **세이브는 "서버가 기준"** — 로그인하면 서버 세이브로 교체하고 이 기기의 솔로 진행은 `emberlands.save.solo`로 백업. 로그아웃 때도 기기 세이브를 백업으로 옮기고 비워서 다른 계정으로 섞이지 않게 함.
- **서버 주소는 같은 origin 기본, `?server=`로 지정(https/localhost만)** — Pages(정적)에서는 서버가 없으면 계정 UI 자체를 숨겨 솔로 동작을 보장.
- **실시간은 중계 위주(M8-2)** — 서버는 위치·채팅·봉화만 중계하고 전투는 아직 각자. 봉화는 "누가 밝히면 모두 켜짐"으로 공유(경험치는 밝힌 사람만, 다른 사람은 퀘스트 진행만).
- **함께 사냥은 owner 클라이언트 방식(B)부터** — 설계는 docs/MULTIPLAYER.md.
